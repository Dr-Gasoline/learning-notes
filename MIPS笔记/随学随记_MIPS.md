# 1. 32个通用寄存器

![alt text](寄存器.png)

补充说明：
- MIPS32 有 32 个通用寄存器，每个宽 32 位。
- `$sp`：保存栈顶地址，压栈通常**先减地址再存数据**（即遵循栈的习惯，先分配空间再存入数据，栈顶指针指向栈顶数据），出栈相反。
- `$ra`：保存返回地址，调用`jal` 时更新，`jr $ra` 根据它返回。
- `HI / LO`：分别对应保存乘法的 **高32位** 和 **低32位** ，或者除法的 **余数** 和 **商** ，使用 `mfhi/mflo` 读取。

实际编程中，常用的变量寄存器主要是`$t0 ~ $t7`和`$s0 ~ $s7`，一般习惯**临时数据用 `$t`，长期数据用 `$s`**，函数中调用`$s`类寄存器时应注意保存和恢复。  
临时 / 长期之分是君子协定，实际存储实现上没有硬性要求，做区分主要是方便理解并维护代码，避免使用时不慎覆盖掉应保留的值。

# 2. 基本概念

## 2.1. 立即数`imm`

**立即数 (immediate)** 是直接写在指令中的数值，不需要先从寄存器或内存中读取。例如：

```mips
addiu $t0, $zero, 5    # $t0 = 0 + 5；5 是立即数
addiu $sp, $sp, -4     # -4 也是立即数
```

立即数可以用十进制或十六进制书写，如 10、0xA。但**写法方便不代表一条机器指令能容纳任意大小的数**：  
许多 MIPS 指令**只有 16 位**的立即数字段，不同指令对它的解释也可能不同（也就是说，很多常用的 I 型指令在机器码中只有 16 位的立即数字段，输入立即数原则上不得超过16位，但见下“另外”）。  
例如，`addiu` 对其进行符号扩展，`ori` 则对其进行零扩展，使立即数达到32位后参与运算并存入32位的寄存器。  
另外，常用的 `li $t0, 0x12345678 `是伪指令，编程形式上可以实现一次存入32位数据，汇编器会根据数值大小，将它转换为若干条真正的机器指令。

## 2.2. 标签`label`

**标签 (label)** 是给某个位置起的名字。写法是在名字后加冒号 `:`  

```mips
.data
number: .word 42

.text
loop:
    addiu $t0, $t0, 1
    j loop
```

上例中，`number` 标记数据所在的地址，`loop` 标记指令所在的地址。  
标签是地址的名字，使用上，“标签的地址”与其关联的 **数据 / 指令块** 的起始地址是相同的；

使用标签时，尤其要分清**地址和地址中的值**：

```mips
la $t0, number       # 将 number 的地址放入 $t0
lw $t1, 0($t0)       # 读取该地址处的一个字；此时 $t1 = 42
```

跳转指令也常使用标签作为目标，例如 `j loop`，这样不必手算目标的具体地址。

## 2.3. 指令结构和类型

一条汇编指令通常由**指令名**和**操作数**组成，`#` 后面是注释：

```mips
addu $t0, $t1, $t2    # $t0 = $t1 + $t2
```

指令名说明“做什么”，操作数说明“对谁操作、结果放到哪里”。上例的结果写入 `$t0`。不过，**不要认为第一个操作数一定是目的地**，例如 `sw $t0, 0($sp)` 是把 `$t0` 中的值写入内存。

从用途看，现阶段可以把常见指令分为以下几类：

| 类别 | 例子 | 主要作用 |
|---|---|---|
| 运算与移位 | `addu`、`subu`、`addiu`、`sll`、<br>`mult`、`div`(、`mfhi`、`mflo`) | 计算数值或处理二进制位 |
| 访存 | `lw`、`sw`、`lb`、`sb` | 在寄存器和内存之间传送数据 |
| 比较与跳转 | `slt`、`beq`、`bne`、`j` | 判断条件或改变执行位置 |
| 函数调用 | `jal`、`jr` | 跳转到函数并返回 |
| 其他 | `syscall` | 请求系统服务 |

从**机器码格式**看，常见指令又分为 R 型、I 型和 J 型。MIPS32 的这些机器指令长度都是 32 位，但内部各部分的分配方式不同：

| 类型 | 基本构成 | 例子 |
|---|---|---|
| R 型 | 操作码、寄存器编号等字段 | `addu`、`sll`、`jr` |
| I 型 | 操作码、寄存器编号、16 位立即数字段 | `addiu`、`lw`、`beq` |
| J 型 | 操作码、26 位目标字段 | `j`、`jal` |

需注意**用途分类和编码分类不是一回事**，二者没有必然关系。

还要区分**机器指令**与**伪指令**。例如 `li`、`la`、`move` 是便于写汇编程序的写法，汇编器会将其转换成一条或多条实际执行的机器指令。因此，源代码中的一行不一定对应一条机器指令。

## 2.4. 访存方式

寄存器数量有限，大量数据需要放在**内存**中。MIPS 的运算指令主要对寄存器进行操作；要使用内存中的数据，通常先用读取指令将它装入寄存器，计算后再按需写回内存。

MIPS 的内存按**字节编址**：每个字节都有自己的地址；一个字（word）占 4 个字节。`lw` 读取一个字，`sw` 写入一个字。它们常用的地址写法是：

```mips
lw $t0, 8($s0)     # 从地址 $s0 + 8 读取一个字，存入 $t0
sw $t0, 8($s0)     # 将 $t0 中的一个字，写到地址 $s0 + 8
```

括号中的寄存器提供**基址**，前面的数提供**偏移量**。偏移量的单位是**字节**，所以访问连续的 `word` 数组元素时，地址通常相差 4。`lw/sw` 访问一个字时，地址还应按 4 字节对齐。

下面是一个完整的例子：

```mips
.data
array: .word 10, 20, 30

.text
    la $t0, array       # $t0 = array 的起始地址
    lw $t1, 4($t0)      # $t1 = array[1] = 20
    sw $t1, 8($t0)      # array[2] = 20
```

这里要特别分清两件事：

- `la $t0, array`：把 **`array` 的地址**放入 `$t0`；`la` 是伪指令。
- `lw $t1, 4($t0)`：从 **`$t0 + 4` 指向的内存**取出一个字，放入 `$t1`。

MARS 还允许某些更简短的标签访存写法，例如直接把标签写在 `lw` 的操作数中。但学习寻址原理时，先使用 `偏移量(基址寄存器)`，更容易看清实际访问的是哪个地址；这也是基础 `lw/sw` 机器指令使用的寻址形式。

## 2.5. 程序骨架

下面是一段可以在 MARS 中运行的简单程序：读取预先定义的整数，将其输出，然后结束。

```mips
.data
number: .word 42        # 定义一个初值为 42 的字

.text
.globl main
main:
    la $t0, number      # $t0 = number 的地址
    lw $a0, 0($t0)      # $a0 = 地址中的值，即 42

    li $v0, 1           # MARS 服务 1：输出整数
    syscall

    li $v0, 10          # MARS 服务 10：结束程序
    syscall
```

程序中各部分的作用如下：

| 内容 | 作用 |
|---|---|
| `.data` | 后续内容放入数据段 |
| `number: .word 42` | 用标签 `number` 标记数据地址，分配一个字并写入初值 `42` |
| `.text` | 后续内容放入存放指令的代码段 |
| `.globl main` | 将 `main` 声明为全局标签 |
| `main:` | 标记下面第一条指令的地址 |
| `syscall` | 按 `$v0` 中的服务编号，请求 MARS 执行相应服务 |

`.data`、`.text`、`.word`、`.globl` 以 `.` 开头，是提供给**汇编器**的指示符，不是 CPU 逐条执行的普通指令。`main:` 是标签，也不是一条指令。

**声明 `.globl main` 不等于执行一次“调用 main”。** MARS 可以通过设置选择从全局标签 `main` 开始运行；若未启用该设置，则按默认的代码段起始地址运行。本例把 `main:` 放在代码段开头，因此无论是否启用该设置，执行都会从这里开始。
