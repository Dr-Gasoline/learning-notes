# 一、一个 Verilog 程序的构建与测试

Verilog 工程以模块为基本单位：模块通过接口交换信号，顶层模块通过实例化组织子模块，testbench 为整个设计提供输入并检查输出。

构建流程通常是：明确功能与时序要求 → 划分模块 → 定义接口 → 实现并连接模块 → 编写 testbench → 运行仿真 → 检查并修正。

## 1. 模块与整体架构

模块由 `module ... endmodule` 定义，是对某一部分电路功能的封装。对模块的使用者而言，首先需要了解它的接口和行为约定，而不必了解内部实现。

划分模块时，应明确 **职责、数据关系、控制关系、时间关系** 等。

同一个模块定义可以被多次实例化，形成多个独立的电路实例。各实例使用同一份定义，但具有各自的连接和内部状态。

## 2. 接口：定义模块的边界

接口是模块与外部交换信号的约定，包括端口名称、方向、位宽，以及信号的含义和生效时间。

### 2.1 端口方向与数据规格

| 端口方向 | 关键字 |
|---|---|
| 输入 | `input` |
| 输出 | `output` |
| 双向 | `inout` |

每个端口还应明确：

- **位宽**：**省略位宽时默认为 1 位**。
- **数值解释**：数据是有符号数、无符号数，还是若干独立的控制位。
- **有效条件**：哪些取值或组合有效，何时可以读取。
- **时序约定**：输入在何时被采样，输出在何时更新、保持多久。
- **控制约定**：时钟的有效边沿、复位的有效电平与同步或异步性质，以及使能、有效信号的含义。

接口定义不仅要说明“传什么”，还要说明“什么时候传、什么时候有效”。

### 2.2 端口方向与信号类型

在基础 Verilog 中，输入输出端口通常按以下方式声明：

| 使用方式 | 常用声明 |
|---|---|
| 模块输入 | `input wire` |
| 由连续赋值或子模块输出驱动的输出 | `output wire` |
| 在 `always` 等过程块中赋值的输出 | `output reg` |
| 双向端口 | `inout wire` |

**语法注意**：  
- 不显式声明类型时，默认类型为 `wire`；
- 同一个类型声明可以声明多个对象，用 `,` 间隔；
- 不同声明类型之间，用 `,` 间隔
- 最后一个声明结束，没有任何符号

e.g.
```verilog
module example(
    input a1, a2, a3,
    // 3 个 1 位宽的 wire
    input [5: 0] n,
    // 1 个 6 位宽的 wire
    output reg res,
    // 1 个 1 位宽的 reg
    output sig  //没有逗号
    // 1 个 1 位宽的 wire
);

//主程序位置

endmodule
```

`reg` 不一定对应实际的硬件寄存器；是否形成存储元件，取决于对电路行为的描述。

连接两侧的类型不要求相同。例如，testbench 中通过过程赋值产生的 `reg` 信号，可以连接到被测模块的 `input wire`。

## 3. 实例化：创建并连接模块

模块定义提供可复用的电路描述，实例化则在上层模块中创建一个具体实例，并连接其端口。

基本格式：

```verilog
模块名 实例名 (
    端口连接
);
```

其中：

- **模块名**指定使用哪一份模块定义。
- **实例名**标识当前创建的具体实例，同一作用域内不能重名。
- **端口连接**规定实例的端口与上层哪些信号相连。

实例化形成电路的层级与连接关系。各实例并行存在，实例化语句的排列顺序不表示运行的先后顺序。

### 3.1 端口连接方式

- **位置映射**按模块定义中的端口排列顺序连接：

```verilog
ModuleName u0(signal_a, signal_b, signal_y);
```

- **名称映射**通过端口名指定连接：

```verilog
ModuleName u0 (
    .a(signal_a),
    .b(signal_b),
    .y(signal_y)
);
```

点号后的名称属于被实例化模块；括号中的名称属于当前上层模块。两侧名称可以不同。

名称映射更便于阅读和维护，通常优先使用。必须为正常工作所需的输入提供有效驱动；不使用的输出可以留空。

### 3.2 连接信号的规则

|子电路内部接口|输入接口|输出接口|
|---|---|---|
|内层声明类型|`wire`|`wire` 或  `reg`|

|子电路对外接口|接受子电路输出|输入子电路|
|---|---|---|
|外层连接类型|`wire`|`wire`、 `reg`、常量或表达式|

实际上逻辑是统一的，不论内层还是外层，从自身信息处理的角度看：  
- 读取外部输入信号时，信号接入到 `wire` ，而 `reg` 必须在过程块中赋值；  
- 向外部输出信号时，仅取信号本身的意义，与输出渠道无关，没有严格的类型要求。  

基础设计中，通常让每个信号具有清晰、唯一的驱动来源；一个来源可以连接到多个接收端。

### 3.3 原语实例化

Verilog 内置了基本门原语，包括 `and`、`nand`、`or`、`nor`、`xor`、`xnor`、`not`、`buf` 等，可以直接实例化。

```verilog
and and1(res, a, b);
//assign res = a & b;
```

原语通过位置映射连接：

- `and` 等多输入门：输出在前，输入在后（类似 MIPS 语法）。
- `not`、`buf` 等可具有多个输出的门：各输出在前，输入在最后。

自定义模块实例必须有实例名，但原语实例化可以省略实例名。

```verilog
and(res, a, b);
```

## 4. Testbench：构建测试环境

testbench 是专门用于仿真的 Verilog 模块，通常没有外部端口。它在内部产生测试信号，实例化被测设计，并观察、检查结果。

testbench 通常包含：

| 组成部分 | 职责 |
|---|---|
| 信号声明 | 定义输入激励、输出连接和辅助变量 |
| 被测模块实例 | 连接需要验证的设计 |
| 初始化与复位 | 建立明确的测试起点 |
| 时钟生成 | 为时序设计提供时钟 |
| 输入激励 | 按测试计划改变输入 |
| 结果检查 | 将实际输出与预期结果比较 |
| 结束控制 | 在测试完成或超时后终止仿真 |

由 `initial`、`always` 驱动的测试信号通常声明为 `reg`；接收被测模块输出的信号通常声明为 `wire`。

被测实例常命名为 `uut` 或 `dut`，二者都只是名称习惯，没有功能区别。

### 4.1 测试的时间安排

testbench 中的时间推进属于仿真环境。`#` 延时的单位由所在代码的 `timescale` 决定。

- **组合电路**：设置输入后，等待输出完成仿真更新，再检查结果。
- **时序电路**：按照接口约定安排时钟、复位、输入采样和结果检查；若输出需要多个周期，就等待相应周期数。
- **复位测试**：同步复位需要经过有效时钟边沿；异步复位还应检查不等待时钟边沿时能否生效。

输入设置和输出检查应避免与时钟采样、寄存器更新发生竞争。


# 二、基本数据类型与运算

## 1. 常用类型与参数

| 数据类型 | 含义 | 特点 |
|---|---|---|
| `wire` | 表示连接，由外部驱动决定其值 | 不存储历史值；可由 `assign`、模块输出或原语输出驱动 |
| `reg` | 在过程块中赋值的变量 | 不一定综合为硬件寄存器，也可以描述组合逻辑 |
| `integer` | 32 位有符号、四态整数变量 | 常用作过程循环索引；参与运算时注意位宽和符号 |

- `wire`、`reg` 省略位宽时均为 **1 位**，不会根据赋值自动扩大。
- `wire`、`reg` 向量默认无符号，使用 `signed` 声明为有符号。
- 普通 `wire` 无驱动时为 `z`；未初始化的 `reg`、`integer` 为 `x`。

| 声明类型 | 含义 | 特点 |
|---|---|---|
| `parameter` | 展开时确定的参数常量 | 实例化时可覆盖，常用于修改模块的输入位宽、内部位宽、生成数量和固定功能选项等 |
| `localparam` | 模块内部的常量 | 不允许实例化时从外部覆盖 |

- `parameter`、`localparam` 是 **常量** 声明方式，并非数据类型，使用时可以指定数据类型，无显式指定时由赋值表达式自动推导。  
需注意，常量声明方式不能亦无意义用于声明运行时变量。  

```verilog
module example #(
    parameter N = 8,       // 由普通十进制整数推导
    parameter SCALE = 0.5, // 实数
    parameter [7:0] MASK = 8'hFF,     // 8 位无符号四态向量
    parameter signed [7:0] OFFSET = -1 // 8 位有符号四态向量
    //参数格式与输入输出相同
)(
    input  wire [N-1:0] a,
    output wire [N-1:0] b
    //接口位宽使用 parameter 的值定义，支持实例化时修改
);

localparam integer COUNT = 16;   // localparam 声明方式同理，但位于模块体内

```

*parameter实例化覆盖*

```verilog
example #(.N(16)) u0 (...);

```

**注意**：  
- `#()` 为固定的语法符号，用于表示参数列表；
- `parameter` 和一个普通的输入变量的核心区别，在于其被解释为常量，可以执行常量行为，如作为 `generate` 的循环边界；
- 参数覆盖值也必须是 **常量** 表达式，不能来自运行时变量。

## 2. 向量与数组

```verilog
reg [31:0] a;             // 一个 32 位向量
reg [31:0] mem [0:1023];  // 1024 个元素，每个元素 32 位

mem[2]       // 下标为 2 的元素，为一个 32 位向量
mem[2][7:0]  // 该元素的低 8 位
```

声明时，名称前的范围表示每个元素的位宽，名称后的范围表示数组索引范围。

```verilog
wire [7:0] a;
wire [0:7] b;
wire [-1:-8] c;
```

声明一个多位宽的向量时，有最高位 `MSB` 和最低位 `LSB` ，$ |MSB - LSB| + 1 $ 表示向量的真实位宽。  
而 `MSB` 和 `LSB` 的具体数值没有位宽意义，仅为标号索引作用，无关实际的数值大小或存储形式。  

## 3. 数字常量与四态值

格式：`位宽'进制数值`，进制标记字母以及 16 进制的字符量都不区分大小写。  

以下示例数值相同：  

| 进制 | 字母 | 示例 |
|---|---|---|
| 二进制 | `b` | `8'b1010_1010` |
| 八进制 | `o` | `8'o252` |
| 十进制 | `d` | `8'd170` |
| 十六进制 | `h` | `8'hAA` |

每一位都有 4 种可能的状态：  

| 值 | 含义 |
|---|---|
| `0`、`1` | 确定的逻辑值 |
| `x` | 未知值 |
| `z` | 高阻态 |

- 位宽按二进制位数计算，与书写进制无关；
- 数值可以使用下划线分隔，无关数值本身，但数值部分不能以下划线开头；
- 未指定进制的普通整数默认为十进制，未指定位宽的整数常量通常存储为至少 32 位，普通无进制整数默认有符号，带进制的整数常量默认无符号；  
- 日常编程中，为了清晰性和可读性，尽量声明清楚一个量的位宽和进制；
- 切片和拼接结果通常按无符号处理；
- 需要有符号量参与运算时，有以下几种方式：   
    - 常量 位宽后 进制前 加 `s` （`8'shFF`）；  
    - 声明时 类型后 位宽前 加 `signed` （`wire signed [3: 0] a`）；  
    - 在需要使用的表达式中用 `$signed()` 进行临时转换（数据类型不变，只是临时被解释为有符号）（`$signed(5'b11111) + $signed(5'b00001)`）。  

**注意**：  
Verilog 表达式的符号属性由操作数和所在表达式的上下文共同决定，不能只看某个变量是否声明为 `signed`。

- 对于 `+`、`-`、`*` 等常见双目算术运算，一个操作数无符号，该运算就按无符号规则进行。
- 三目运算符 `? : ` 会根据两个结果分支统一符号属性，即使其中一个分支不会被选中也会参与判断。无符号属性可能向分支内部传播，使原本使用 `$signed()` 的算术右移变成补 0。
- 移位次数、三目运算符的条件等，不参与这种符号属性的统一。
- 需要有符号运算时，应检查参与运算的各个操作数和结果分支，尽量保持为全部有符号。必要时用有符号中间变量拆分计算，避免外层表达式影响内部运算。 

**注意**：  
在不同位宽量之间进行赋值时，若右侧过宽会截去高位保留低位，过窄则按右侧表达式的符号属性进行零扩展或符号扩展，拼接赋值规则相同。  
一般的通用逻辑是 **隐式修改右侧位宽至与左侧对齐**。  
进行不同位宽的转换和赋值时，为确保程序行为清晰可解释，推荐进行手动的显式扩展 / 截断。

```verilog
// a 为 8 位、y 为 16 位
assign y = {8'b0, a};          // 显式零扩展
assign y = {{8{a[7]}}, a};     // 显式符号扩展
```

需要保留进位时，可先显式扩展操作数：

```verilog
wire [8:0] sum;
assign sum = {1'b0, a} + {1'b0, b};
```

## 4. 运算符

### 4.1 位运算、逻辑运算与归约运算

- 位运算：`&`、`|`、`^`、`~` 等。
- 逻辑运算：`&&`、`||`、`!`，按整个操作数的真假计算。
- 归约运算：单目 `&`、`|`、`^` 等，将各位汇总成 1 位结果。

```verilog
a & b   // 对应位分别做与运算，结果可以是多位
a && b  // 判断两者是否都为真，结果只有 1 位
&a      // 将 a 的所有位做与运算，结果只有 1 位
```

逻辑运算和归约运算遇到未知位时，结果可能为 `x`。

### 4.2 相等比较

| 运算符 | 对 `x`、`z` 的处理 |
|---|---|
| `==`、`!=` | 无法确定比较结果时返回 `x` |
| `===`、`!==` | 将 `x`、`z` 作为待比较的状态，结果一定是 0 或 1 |

testbench 检查结果时常用：

```verilog
if (out !== expected)
    $display("ERROR");
```

这样输出中出现未知值时，也能报告不匹配。

### 4.3 位移

| 运算符 | 填充值 |
|---|---|
| `>>`、`<<`、`<<<` | 补 0 |
| `>>>` | 左操作数为**有符号数**时补符号位，否则仍补 0 |

`>>>` 不自动按符号位扩展，要实现算数右移，还要确认左侧操作数为有符号量。

## 5. 拼接

```verilog
{a, b}                 // a 在高位，b 在低位
{4{a}}                 // 等价于 {a, a, a, a}
```

- 拼接结果的位宽是各部分位宽之和；
- 重复次数必须是常量表达式，不能由运行时输入决定；
- 被拼接子串应使用明确位宽的常量，避免未定宽整数造成歧义或编译错误；
- 拼接也可以放在赋值左侧，用于将一个多位宽量分割给几个变量：

```verilog
// B 为 2 位宽 reg , A 为 1 位宽 reg
{B, A} = 3'b101;  // B = 2'b10，A = 1'b1
```

## 6. 赋值

| 写法 | 含义 | 位置 |
|---|---|---|
| `assign y = expression;` | 持续驱动连接 | 模块内 |
| `y = expression;` | 阻塞赋值，赋值完成后执行后续语句 | 过程块内，如 `initial` 、`always` |
| `y <= expression;` | 非阻塞赋值，先计算右值，将左值更新安排到非阻塞更新阶段 | 同上 |

## 7. 宏定义

```verilog
//定义
`define WORDSIZE 8
//使用
 reg[1:`WORDSIZE] data;

```

**注意**：引用宏名时也必须在宏名前加上符号 `` ` ``。

# 三、程序中信号的处理

## 1. 连续赋值 `assign` ：  

```verilog
assign sig = expression;
//sig 为 wire ，expression 为数据和运算符组成的表达式
```
`assign` 语句的作用是将右侧表达式的值持续性的赋给左侧的 `wire` 信号，一般用于描述一个信号是如何由其他信号生成的，**当右侧表达式中的变量发生变化时，左侧信号的值也会随之变化**。

`assign` 语句非常适合简单的组合逻辑的描述，经常与三目运算符配合使用，类似于 MUX 实现不同的接线连通。  

## 2. 过程控制：

过程控制语句**不能直接存在于模块内**，一般只能在 `initial` 或 `always` 结构中出现。  

### 2.1. `initial` 结构
e.g.
```verilog

reg [4:0] a;
integer i;

initial begin
    a = 5'b10101;
    i = 0;
end
```

从仿真 0 时刻开始执行，在整个仿真过程中只执行一次。  
用途：
- 功能程序中常用于 `reg` 或 `integer` 的初始化赋值；  
- 测试程序中生成测试输入，控制测试流程。  

**区分**： `wire` 的值由 `assign`连续赋值 或 模块输出 在结构外部自动确定，不能也没必要进行 `initial` 赋值。

### 2.2. `always` 结构
e.g.
```verilog
always@( 敏感条件 ) begin
    //过程执行程序

end
```

**敏感条件**：  
- `always begin`；无条件执行，一次执行完毕后，立即重新开始执行。
一般配合延迟语句在 testbench 的编写中使用，例如：`always #5 clk = ~clk`；  

- `always@(*) begin`：自动根据过程块中读取的信号建立敏感列表，任一读取变量变化时会引起该 `always` 结构的执行（结构内的赋值操作并没有影响）；  

- 边沿敏感 `always@(posedge clk, negedge rst_n)`：信号在处于上升沿/下降沿的时候会执行结构中的语句，用于时序逻辑；  

- 电平敏感 `always@(sig)`：该信号发生改变（注意**不是为真**）时会执行结构中的语句，常用于组合逻辑；

- 多个敏感条件之间用 `or` 或者 `,` 连接。

### 2.3. 过程控制语句

语法与 C 中一致，区别在于 `{}` $\to$ `begin-end`，但行为一致（当且仅当单语句可以不加）  
- `if-else` 
- `while` 
- `for` 

```verilog
for (i = 0; i < 8; i = i + 1)
	statement;
```

**注意**：  
`for` 语句中不能直接声明临时索引变量，且不支持 `i++` 等自增、自减语法。  
使用具名 `begin-end` 块可以在作用域内声明临时变量：

```verilog
always @(*) begin : calc
    integer i;
    //变量 i 的作用域仅限于这个 `begin-end` 语句块中
    for (i = 0; i < 8; i = i + 1)
        out[i] = a[i];
end
```

- `case`

```verilog
always @(posedge clk) begin
  case(data)
      0: out <= 4;
      1: out <= 5;
      2: out <= 2;
      3: begin
          out <= 1;
      end
      default: ;
  endcase
end
```

**注意**：  
与 C 语言不同，`case` 语句在分支执行结束后不会落入下一个分支，而会自动退出；   
`case` 语句进行的是全等比较，也就是每一位都相等（包括 x 和 z）才认为相等

# 四、for 循环的 generate 实现

## 1. 两种 `for` 循环：

- **`always` 中的 `for`**：描述一个过程块内部重复执行的操作。
- **`generate` 中的 `for`**：在仿真开始前的 **展开阶段（elaboration）** 生成多份电路结构。

## 2. always 中的 for：过程循环

以一个简单的分段饱和加法程序为例：  
把两个 32 位输入看成 4 组独立的 8 位无符号数，对应字节相加，超过 255 时输出 255。

```verilog
module sat_add(
    input  wire [31:0] a,
    input  wire [31:0] b,
    output wire [31:0] out
);
    integer i;
    reg [8:0] aa, bb, sum;
    reg [7:0] ans [0:3];

    assign out = {ans[3], ans[2], ans[1], ans[0]};

    always @(*) begin
        for (i = 0; i < 32; i = i + 8) begin
            aa = {1'b0, a[i +: 8]};
            bb = {1'b0, b[i +: 8]};
            sum = aa + bb;

            if (sum[8])
                ans[i / 8] = 8'hff;
            else
                ans[i / 8] = sum[7:0];
        end
    end
endmodule
```

### 2.1 仿真时如何执行

相关输入变化后，`always @(*)` 被触发，循环依次取：

```text
i = 0、8、16、24
```

每轮读取一个字节，用阻塞赋值 `=` 依次计算 `aa`、`bb`、`sum`，再写入对应的 `ans` 元素。

- `aa`、`bb`、`sum` 是**同一组过程变量**，在循环中反复使用。
- 4 个 `ans` 元素每次执行都会得到赋值。
- 代码没有等待时钟或延时，因此循环在同一个仿真时间点内完成，**不需要 4 个时钟周期**。

*特殊语法*：可变位置的切片

```verilog
a[i +: 8]
```

表示从第 `i` 位开始，向编号增大的方向取 8 位，如 `i=0` 时表示 `a[7 : 0]` ，这里起始位置可以变化，但宽度 `8` 必须是常量。

传统范围选择要求边界为常量，普通过程变量 `i` 不能直接使用：

```verilog
a[i + 7 : i]  // i 是过程变量时不合法
```

## 3. generate 中的 for：生成重复结构

同一功能可以写为：

```verilog
module sat_add(
    input  wire [31:0] a,
    input  wire [31:0] b,
    output wire [31:0] out
);
    genvar i;

    generate
        for (i = 0; i < 4; i = i + 1) begin : byte_add
            wire [8:0] sum;

            assign sum = {1'b0, a[8*i+7 : 8*i]}
                       + {1'b0, b[8*i+7 : 8*i]};

            assign out[8*i+7 : 8*i] =
                sum[8] ? 8'hff : sum[7:0];
        end
    endgenerate
endmodule
```

### 3.1 genvar 是什么

```verilog
genvar i;
```

`genvar` 声明的是**展开阶段使用的生成循环索引**。

- 它用于确定生成多少份结构，以及各份结构使用哪些位段。
- 在每个生成块内部，对应的索引值已经固定，满足常量要求。
- 它不会成为电路中的计数器，也不会在仿真过程中随时钟变化。

因此，这里的 `8*i+7` 和 `8*i` 在展开后都是常量，可以用于传统范围选择。

### 3.2 每一轮生成独立的作用域

```verilog
begin : byte_add
    wire [8:0] sum;
    // ...
end
```

`byte_add` 是生成块的名字。循环展开后，得到四份独立结构：

| 展开索引 | 处理位段 | 独立的中间信号 |
|---|---|---|
| 0 | `[7:0]` | `byte_add[0].sum` |
| 1 | `[15:8]` | `byte_add[1].sum` |
| 2 | `[23:16]` | `byte_add[2].sum` |
| 3 | `[31:24]` | `byte_add[3].sum` |

虽然源码只写了一条 `sum` 声明，实际生成了四根不同的信号。

仿真开始后，结构已经固定。内部的四组 `assign` 持续响应输入变化，`generate` 本身不会随输入重新展开。

## 4. generate 的基本语法要求

| 项目 | 要求或建议 |
|---|---|
| 所处位置 | 在 `module` 内、`always` 和 `initial` 外 |
| 外层范围 | 使用 `generate ... endgenerate` |
| 循环索引 | 使用 `genvar` |
| 循环控制 | 循环边界、步长等必须在展开时确定，通常使用常量或参数 |
| 循环步进 | 写 `i = i + 1` |
| 生成块 | 使用 `begin : 块名 ... end`，明确命名 |
| 块内内容 | 可以有信号声明、`assign`、模块实例、`always` 等 |

生成块仍然要遵守普通赋值规则：

```verilog
generate
    assign y = a & b;   // 连续赋值，可以
    // y = a & b;       // 裸露的过程赋值，不可以
endgenerate
```

若需要过程赋值，应放进 `always` 或 `initial` 中，而不能直接放在生成块里。

## 5. 条件生成：if 和 case

除了循环生成，`generate` 还能根据常量条件选择结构。

下面的示例均写在模块内部，假设 `a`、`b`、`y` 已声明；两个示例分别使用。

### 5.1 generate-if

```verilog
parameter USE_ADD = 1;

generate
    if (USE_ADD == 1) begin : g_add
        assign y = a + b;
    end
    else begin : g_sub
        assign y = a - b;
    end
endgenerate
```

`USE_ADD` 是参数，展开时就能确定：

- 为 `1`：生成加法分支。
- 为其他值：生成减法分支。

### 5.2 generate-case

```verilog
parameter MODE = 0;

generate
    case (MODE)
        0: begin : g_and
            assign y = a & b;
        end
        1: begin : g_or
            assign y = a | b;
        end
        default: begin : g_xor
            assign y = a ^ b;
        end
    endcase
endgenerate
```

`generate-if` 和 `generate-case` 本身不需要 `genvar`。

### 5.3 条件生成与运行时选择

决定生成结构的条件必须在展开时确定，不能使用会在运行时变化的输入信号。

若想用输入 `sel` 实时选择加减法，应写：

```verilog
assign y = sel ? (a + b) : (a - b);
```

只要求“生成多少份、生成哪种结构”提前确定；生成出的电路内部，输入、输出和时钟都可以正常变化。

## 6. generate 可以包含 always

例如，下面的代码片段生成四个时钟过程块。假设 `clk` 和 4 位输入 `d` 已声明：

```verilog
reg [3:0] q;
genvar k;

generate
    for (k = 0; k < 4; k = k + 1) begin : regs
        always @(posedge clk) begin
            q[k] <= d[k];
        end
    end
endgenerate
```

- `generate` 决定建立四份结构。
- 每份结构中的 `always` 决定在时钟上升沿更新对应的数据位。

四个过程块分别驱动 `q` 的不同位，没有重复驱动同一位。

## 7. 对照与使用建议

| 对比项 | 过程式 for（always、initial 内） | generate 中的 for |
|---|---|---|
| 主要作用 | 描述重复的过程操作 | 生成重复的电路结构 |
| 循环索引 | 常用 `integer` | 使用 `genvar` |
| 仿真中的行为 | 过程被触发后执行循环 | 仿真前完成结构展开 |
| 临时变量 | 可在循环中反复使用同一组变量 | 块内声明为每份结构分别建立对象 |
| 典型用途 | 组合计算、固定范围遍历、批量复位 | 重复实例化、并列电路、参数化结构 |
| 循环边界 | 常量、参数、运行时变量、表达式（用于综合时通常要求边界可静态确定） | **必须在展开时确定**<br>常量、参数、相关常量表达式，也可依赖外层生成索引；<br>**不能使用运行时信号**（如输入端口 `input` 、`wire`、`reg`、`integer` 等） |


# 五、常用系统任务与系统函数

以下功能主要用于 testbench。系统任务放在 `initial`、`always` 等过程块中，系统函数可以作为表达式使用。

## 1. 输出：`$display`、`$write`

```verilog
$display("a=%0d, b=%0h", a, b);
$write("Hello");
```

- `$display`：输出后自动换行。
- `$write`：输出后不自动换行。
- 格式符与后面的表达式按顺序对应；数字格式前加 `0` 可去掉多余填充。

| 格式符 | 含义 |
|---|---|
| `%b` | 二进制 |
| `%o` | 八进制 |
| `%d` | 十进制 |
| `%h` | 十六进制 |
| `%s` | 字符串 |
| `%t` | 时间 |
| `%%` | 字符 `%` |

## 2. 监视信号：`$monitor`

执行一次后，所列信号变化时自动输出：

```verilog
initial
    $monitor("time=%0t, a=%0h, out=%0h", $time, a, out);
```

## 3. 仿真时间：`$time`

返回当前仿真时间：

```verilog
$display("time=%0t", $time);
```

## 4. 结束或暂停：`$finish`、`$stop`

```verilog
$finish;  // 结束整个仿真
$stop;    // 暂停仿真，供交互调试
```

测试结束时通常使用 `$finish`，尤其是存在持续产生时钟的过程时。

## 5. 加载测试数据：`$readmemh`、`$readmemb`

```verilog
reg [31:0] mem [0:255];

initial begin
    $readmemh("code.txt", mem);
end
```

- `$readmemh`：读取十六进制数据。
- `$readmemb`：读取二进制数据。
- 参数顺序：文件名、数组名、可选的起始下标、结束下标。

```verilog
$readmemh("code.txt", mem, 0, 127);
```

下标表示数组元素的位置；相对文件路径以仿真器运行目录为依据。

## 6. 随机输入：`$random`

返回 32 位有符号伪随机数：

```verilog
a = $random;
```

赋给较窄变量时保留低位。结果可能为负，直接使用 `$random % N` 不保证得到非负数。
